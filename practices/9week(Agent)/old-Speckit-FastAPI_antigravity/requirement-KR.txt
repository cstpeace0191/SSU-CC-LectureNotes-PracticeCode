1. 프로젝트 개요
--------------------------------------------------------------------------
- Docker 공식 샘플 "getting-started-todo-app"을 기반으로, 원래 Node.js(Express)
  백엔드를 Python FastAPI + Uvicorn(비동기) 백엔드로 변환한 Todo 리스트 웹 앱.
- 프론트엔드: React 19 + Vite 6 + React-Bootstrap (SPA)
- 백엔드:     FastAPI (Python 3.12), REST API 제공 + 빌드된 SPA 정적 파일 서빙
- 데이터베이스: SQLite(기본, 로컬) 또는 MySQL(환경변수 지정 시, Docker Compose 개발환경)
- 실행 환경: Docker Compose (Traefik 리버스 프록시 + backend + client + MySQL + phpMyAdmin)
             또는 Windows 로컬 직접 실행

3. 기능 요구사항 (Functional Requirements)
--------------------------------------------------------------------------
FR-01  인사말 표시: 화면 상단에 서버에서 받은 인사말("Hello world!")을 표시한다.
FR-02  할 일 목록 조회: 저장된 모든 Todo 항목을 조회하여 표시한다.
       항목이 없으면 "No items yet! Add one above!"를 표시한다.
FR-03  할 일 추가: 이름을 입력하여 새 항목을 추가한다.
       - 이름은 1자 이상이어야 한다 (빈 값이면 버튼 비활성화 + 서버 422 검증).
       - ID는 서버에서 UUID v4로 생성, completed 기본값 false.
FR-04  완료 상태 토글: 체크박스 아이콘 클릭으로 completed 값을 반전한다.
FR-05  할 일 수정: name/completed 중 전달된 필드만 부분 수정한다.
       존재하지 않는 ID이면 404 "Item not found"를 반환한다.
FR-06  할 일 삭제: 휴지통 아이콘 클릭으로 항목을 삭제한다.
FR-07  데이터 영속성: 서버/컨테이너 재시작 후에도 데이터가 유지된다
       (SQLite 파일 또는 MySQL 볼륨 todo-mysql-data).


4. REST API 명세
--------------------------------------------------------------------------
 (모든 엔드포인트는 /api 접두사 버전과, 스키마에 숨겨진 접두사 없는 별칭을 함께 제공)

 메서드  경로                    요청 본문                          응답
 ------  ----------------------  ---------------------------------  -----------------------------
 GET     /api/greeting           -                                  200 {"greeting": "Hello world!"}
 GET     /api/items              -                                  200 [Item, ...]
 POST    /api/items              {"name": str(1자 이상)}            200 Item  / 422 검증 실패
 PUT     /api/items/{item_id}    {"name"?: str, "completed"?: bool} 200 Item  / 404 없음
 DELETE  /api/items/{item_id}    -                                  200 (본문 없음)
 GET     /docs                   FastAPI 자동 생성 Swagger UI
 GET     /  (그 외 경로)         backend/src/static 의 React SPA (디렉터리 존재 시)

 Item 모델: { "id": str(UUID), "name": str, "completed": bool }


5. 데이터 저장소 요구사항
--------------------------------------------------------------------------
- 테이블: todo_items (id VARCHAR(36), name VARCHAR(255), completed BOOLEAN)
  - 앱 시작 시 CREATE TABLE IF NOT EXISTS 로 자동 생성.
- 저장소 선택 규칙:
  - MYSQL_HOST 또는 MYSQL_HOST_FILE 환경변수가 있으면 MySQL, 없으면 SQLite.
- SQLite
  - 경로: SQLITE_DB_LOCATION (기본 /etc/todos/todo.db, 상위 폴더 자동 생성)
  - Windows 로컬 실행 시 기본 경로 대신 SQLITE_DB_LOCATION 지정 권장.
- MySQL
  - 접속 정보: MYSQL_HOST / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DB
    (각각 *_FILE 변수로 Docker secret 파일 경로 지정 가능)
  - 기본값: localhost / root / "" / todos, 포트 3306 고정, utf8mb4
  - 커넥션 풀 min 1 / max 5, autocommit
  - DB 준비 대기: 1초 간격 최대 30회 재시도


6. 비기능 요구사항 (Non-Functional Requirements)
--------------------------------------------------------------------------
NFR-01 비동기 처리: FastAPI + aiosqlite/aiomysql 로 모든 DB I/O를 async 처리.
NFR-02 CORS: 개발 편의를 위해 모든 Origin/메서드/헤더 허용 (운영 시 제한 필요).
NFR-03 Windows 호환: Windows 레지스트리의 잘못된 MIME 타입 문제를 막기 위해
       .js/.mjs/.css/.svg/.json/.ico MIME 타입을 코드에서 강제 등록.
NFR-04 테스트: pytest + pytest-asyncio + httpx(ASGITransport)로 라우트/영속성 테스트.
       Docker 'test' 스테이지에서 테스트가 통과해야 'final' 이미지가 빌드됨.
NFR-05 개발 생산성: Compose Watch로 소스 변경 시 컨테이너에 자동 동기화,
       uvicorn --reload / Vite HMR로 자동 재시작.
NFR-06 단일 배포: final 이미지는 React 빌드 결과를 FastAPI가 직접 서빙(포트 3000)하는
       단일 컨테이너로 구성.

8. 실행 환경 구성
--------------------------------------------------------------------------
8-1. Docker Compose 개발 환경 (권장)
   docker compose watch      (또는 docker compose up --build)
   - http://localhost          → client (Vite, 5173)
   - http://localhost/api/*    → backend (FastAPI, 3000)
   - http://db.localhost       → phpMyAdmin
   - Traefik이 80 포트에서 Host/PathPrefix 라벨 규칙으로 라우팅.
   - backend는 mysql 헬스체크(mysqladmin ping) 통과 후 시작.

8-2. 운영(단일) 이미지
   docker build -t todo-app .            (target 기본값 = final)
   docker run -p 3000:3000 todo-app      → http://localhost:3000
   - 이 경우 MySQL 환경변수가 없으므로 SQLite 사용.

8-3. Windows 로컬 직접 실행
   (백엔드)  cd backend
             python -m venv .venv  →  .venv\Scripts\activate
             pip install -r requirements.txt
             python main.py                   → http://localhost:3000
   (프론트)  cd client
             npm install
             npm run dev                      → http://localhost:5173 (/api 는 3000으로 프록시)
             npm run build                    → dist 생성 후 backend/src/static 으로 복사
   (테스트)  cd backend  →  pytest

10. 참고 / 확인 필요 사항
--------------------------------------------------------------------------
- client/package.json 의 dependencies에 'prop-types'가 명시돼 있지 않음.
  (컴포넌트에서 import 하지만 다른 패키지의 하위 의존성으로 설치되어 동작 중 →
   명시적으로 추가 권장)
- ItemDisplay.jsx 의 className `item ${item.completed && 'completed'}` 는
  미완료 시 "item false" 클래스가 붙음 (동작 영향은 없음).
- Compose 파일의 DB 비밀번호(secret)는 개발용 하드코딩 값 → 운영 시 secret/환경변수 사용.
- 기존 Node.js 백엔드 파일(backend/src/*.js, spec/*.spec.js, package.json)과
  루트 README.md는 삭제되었고, 새 Python 파일들은 아직 git에 커밋되지 않은 상태.
- backend/.venv, .pytest_cache, client/dist, backend/src/static 은
  .gitignore 대상인지 확인 권장.
